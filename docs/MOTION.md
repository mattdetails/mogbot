# Motion

One motion system for the desk (Mac, Windows, Linux) and the phone (iPhone, Android). Owner: Mogbot
Motion. Look and layout belong to Designer's specs; this file says how things move, and every
spec's Motion section points here instead of inventing numbers.

**The numbers live in one file:** `packages/companion-protocol/src/motion.ts`. The desk mirrors
them as CSS custom properties in `src/styles/global/tokens-core.css`, and
`src/lib/motionTokens.test.ts` fails if the two drift. The phone imports them directly. Never write
a duration, curve or spring anywhere else.

**The reference is Grok Bot.** Replies land whole (no streaming in), one quiet working line while
it works, nothing bounces. Mogbot should feel at least as quick and calm, on every platform.

## Principles

1. **Motion explains, it doesn't perform.** It says where something came from, where it went, or
   that the app heard you. If it does none of those, it doesn't move.
2. **Fast in, faster out.** Arrivals 150–300ms; exits about two thirds of that. Nobody waits for
   something to leave.
3. **Every enter has an exit.** Nothing that animates in may vanish in one frame, and nothing
   around it may jump when it goes.
4. **Only transform and opacity.** Never animate height, width, top/left, margin, padding or
   grid tracks. When the layout must change size, change it in one frame and animate a transform
   that hides the jump (FLIP), or crossfade.
5. **One curve per job.** Arriving, leaving, moving, pressing. Same job, same curve, everywhere.
6. **Respect Reduce Motion, live.** It changes at any time; read it live, never once at launch.
7. **Measure, don't guess.** A change ships with a trace (desk: Chrome/Safari performance panel
   on the harness; phone: Reanimated/Perf Monitor on a real device or the simulator) showing it
   holds 60fps, 120 on ProMotion.

## Tokens

| Token (TS / CSS) | Value | Use |
|---|---|---|
| `press` / `--duration-press` | 70ms | A press acknowledged |
| `micro` / `--duration-micro` | 100ms | Hover, colour, border |
| `quick` / `--duration-quick` | 150ms | Small change in place: toggle, chip, text swap |
| `arrive` / `--duration-arrive` | 200ms | A message, card, menu, popover, toast arriving |
| `screen` / `--duration-screen` | 300ms | A modal, sheet, screen or panel arriving |
| `exitQuick` / `--duration-exit-quick` | 120ms | Menus, popovers, toasts leaving |
| `exitScreen` / `--duration-exit-screen` | 200ms | Modals, sheets, screens leaving |
| `reduced` / `--duration-reduced` | 0.01ms | Under Reduce Motion (still fires the end event) |
| `pulse` / `--duration-pulse` | 1600ms | One beat of a loop asking for attention: needs your OK, a skeleton, the busy glow |
| `breathe` / `--duration-breathe` | 2400ms | One breath of a loop saying "working" |

| Curve | Value | Use |
|---|---|---|
| `arrive` / `--ease-arrive` | cubic-bezier(0.16, 1, 0.3, 1) | Every entrance |
| `exit` / `--ease-exit` | cubic-bezier(0.4, 0, 1, 1) | Every exit |
| `move` / `--ease-move` | cubic-bezier(0.2, 0, 0, 1) | On-screen to on-screen: reorder, resize, indicator |
| `press` / `--ease-press` | cubic-bezier(0.3, 0.7, 0.4, 1) | A press going down |
| `standard` | cubic-bezier(0.25, 0.1, 0.25, 1) (= CSS `ease`) | Colour/opacity with no travel |
| `loop` / `--ease-loop` | cubic-bezier(0.42, 0, 0.58, 1) (= CSS `ease-in-out`) | Loops: a pulse, a breath |
| linear | | Progress and spinners only |

**Springs** are given as perceived duration and damping ratio, which is how Reanimated 4 takes them
(`withSpring(v, { duration, dampingRatio })`). The desk renders the same curves with CSS `linear()`
(`--spring-*`, generated by `springEasing()` and paired with `--duration-spring-*`), falling back to
`--ease-move` where `linear()` isn't supported.

| Spring | Duration | Damping | Use |
|---|---|---|---|
| `snappy` | 250ms | 1 (no overshoot) | Press release, toggle, chip, send button |
| `standard` | 380ms | 0.92 | Sheets, cards, panels settling; reorders; a swipe returning |
| `celebrate` | 500ms | 0.7 | Only a moment worth marking: Paired, a first result |

**CSS roles** (`tokens-semantic.css`), what specs and desk code name:

| Role | Is | Use |
|---|---|---|
| `--motion-hover` | micro + standard | Hover in and out |
| `--motion-change` | quick + standard | A state changing in place |
| `--motion-press` | press + press | Going down |
| `--motion-release` | spring snappy | Coming back up |
| `--motion-arrive` | arrive + arrive | Anything arriving (menus, messages, cards, toasts) |
| `--motion-screen` | screen + arrive | Modals, screens, panels arriving |
| `--motion-exit` | exitQuick + exit | Menus, popovers, toasts leaving |
| `--motion-exit-screen` | exitScreen + exit | Modals, screens leaving |
| `--motion-move` | spring standard | On-screen moves: reorder, restack, a swipe returning |
| `--motion-pop` | spring celebrate | Paired, a first result |
| `--motion-pulse` | pulse + loop, with `infinite` | A loop asking for attention; opacity or transform only |
| `--motion-breathe` | breathe + loop, with `infinite` | A loop saying "working"; opacity or transform only |

On the phone, `mobile/src/lib/motion.ts` exposes the same names as Reanimated configs.

**Distances:** popover/menu 4px from its trigger, starting at scale 0.97; a message, card or toast
rises 8px; a desk modal starts at scale 0.98; a pressed control goes to 0.97. Never scale from 0.

**Stagger:** 30ms per item, at most 6 items (the rest arrive with the sixth).

## Rules by kind

| Thing | Enter | Exit | Notes |
|---|---|---|---|
| Message you sent | Instantly in place, rise 8px + fade, `arrive` | — | Optimistic: it's there the frame you press Send |
| Agent's reply | Lands whole: rise 8px + fade, `arrive`, while the working line crossfades out in the same frame | — | The reply takes the working line's slot; the transcript doesn't move. No per-word reveal (Grok) |
| Working line | Fade, `quick` | Crossfade into the reply | Its height is reserved, never animated |
| Card (approval, result, plan) | Like a reply | Answered: the buttons crossfade to the outcome in place, `quick` | Height changes in one frame, hidden by the crossfade |
| History, switching agents | Opacity only, `quick` | — | Lands already scrolled to the bottom; nothing travels |
| Menu, dropdown, popover | Fade + 4px from trigger + scale 0.97, `arrive` | Fade, `exitQuick`, `exit` | All menus share one keyframe pair (`ss-context-menu-*`) |
| Modal, dialog, Settings | Scrim fade `screen`; dialog fade + scale 0.98, `screen` | Both fade, `exitScreen`, `exit` | Through `ModalFrame`, so every modal gets it |
| Sheet (phone) | Native sheet | Native | Never re-implement the system sheet |
| Screen (phone) | Native stack push | Native pop | Modal flows `slide_from_bottom`; viewers `fade` |
| Toast | Rise 8px + fade, `arrive` | Fade + 4px down, `exitQuick`; the rest restack with `spring.standard` | Never just unmount |
| Sidebar row | New: rise, `arrive`. Reorder: FLIP transform, `spring.standard` | Fade + collapse via FLIP of the rows below, `exitQuick` | Hover `micro`, selected instant |
| Press | `press` to scale 0.97 / pressed tint | Release on `spring.snappy` | Desk and phone alike |
| Hover | Background `micro` | Same | One duration for every hover |
| Composer growth | Height changes in one frame; the transcript stays pinned | — | No height transition, no forced reflow per keystroke |
| Jump to latest | Fade + rise 4px, `arrive` | Fade, `exitQuick` | Scroll itself: instant under Reduce Motion |
| Swipe (reply, catch up, row actions) | Follows the finger 1:1 on the UI thread | Returns on `spring.standard` | Haptic `select` at the threshold, not on release |
| Progress bars | Transform `scaleX`, `move`, `screen` | — | Never `width` |
| Loaders, shimmer, typing dots | Loop | — | Pause when hidden, backgrounded or scrolled off screen |

## Scroll and keyboard

- Pinned to the bottom (within 80px): new content keeps it pinned in the same frame (no smooth
  scroll racing a layout change). Scrolled up: nothing moves; the Jump to latest pill appears.
- Opening a chat lands at the bottom with no visible scroll.
- One scroll write per frame at most, from one place (`useFollowBottom` desk, `follow.ts` phone).
- Phone keyboard: the composer and everything above it ride the keyboard's own animation on the UI
  thread (`react-native-keyboard-controller`), never a JS re-render per frame.

## Reduce Motion

- Desk: `prefers-reduced-motion: reduce` → `--duration-reduced` for everything (the global floor in
  `base.css`). No translate or scale; opacity changes stay but are instant. Mark what carries
  meaning with `data-motion="essential"` (search-hit flash, a spinner) so it survives.
- Phone: Reanimated's `ReduceMotion.System` on every animation, and the live `useReduceMotion()`
  from `lib/moving.ts`, never Reanimated's launch-time `useReducedMotion()`. Stack transitions
  become `fade`. Loops stop; a spinner becomes a static mark.
- Scroll: instant (`scrollMotion()` desk).

## Haptics (phone)

`HAPTICS` in `motion.ts` maps events to the six kinds `mobile/src/lib/haptics.ts` plays. Settings →
Haptics turns them all off.

| Event | Haptic |
|---|---|
| Sent, or queued for the next turn | light |
| Stopped / interrupted a turn; hold to talk | medium |
| A swipe crosses its threshold; a toggle flips; a pick in a picker | select |
| Long-press opens a menu | medium |
| Pull to refresh crosses its trigger | select |
| An approval the Mac confirmed allowed; paired; copied | success |
| An approval the Mac confirmed denied | warning |
| It didn't happen | error |

Silent: navigation, a reply or card arriving, scrolling, a refresh finishing.

## Performance budget

- Animate only `transform` and `opacity` (desk and phone). `filter` and `box-shadow` only on
  elements under 200×200.
- Desk: no layout reads inside a rAF/scroll/ResizeObserver callback that also writes; batch reads,
  then writes. `will-change` only during the animation.
- Phone: every animation on the UI thread (Reanimated worklets, gesture-handler gestures). No
  `setState` per frame; no `PanResponder`; no `LayoutAnimation`.
- Targets: 60fps on a 2019 Intel Mac and a mid-range Android; 120fps on ProMotion. Any dropped
  frame in a recorded trace of a chat reply landing is a bug.

## Audit, 19 Nov 2026

The inventory behind this spec. File:line references are on `mogbot-motion/start-with-the-audit-8bc7`.
Recordings (harness, dark, real time) are in Motion's folder, `rec/`.

**Desk, worst first**

1. Modals have no motion at all except the New agent and Import dialogs, and none has an exit:
   `ModalFrame.tsx:467` returns null when closed; `modal-frame.css`/`modal.css` have no motion.
   Settings, ⌘K, Apps and Files appear and vanish in one frame. *Recorded: `01-modals-pop.mp4`.*
2. Three menus in one header, three behaviours, no exits: the model menu snaps open, Conversations
   fades, ⋯ scales in (`dropdown.css` base menu has no motion; `agents-motion.css:334` only covers two
   menus). *Recorded: `02-menus-mixed.mp4`.*
3. Streaming reply re-renders React and writes scroll every frame (`useReveal.ts:82-95`,
   `useAgentMotion.ts:212`). Moot once replies land whole (spec), but the code must go.
4. The working line opens and closes by animating height (`agents-motion.css:67-85, 202, 207`),
   re-laying out the transcript each frame as the reply lands.
5. Composer growth animates height with a forced reflow per keystroke (`agents-motion.css:271`,
   `AgentComposer.tsx:262-268`); the transcript jumps a line at the first newline.
   *Recorded: `04-composer-grow.mp4`.*
6. Toasts unmount with no exit and the stack jumps (`ToastList.tsx:117`).
7. What's in flight folds cards by height/padding/margin, on a 700ms JS timer against a 250ms CSS
   curve (`agents-team.css:280`, `AgentsTeamView.tsx:356`).
8. Queue hint eases open, snaps shut (`agents-composer.css:234`).
9. No element sets `data-motion="essential"`, so the search-hit flash dies under Reduce Motion,
   against its own comment (`agents-motion.css:350`, `base.css:659`).
10. Raw values: `agent-activity.css` (nine, with an overshoot bezier), `transition: all` in
    `setup-agent-led.css:63` and `account-select.css:165`, the onboarding progress fill that never
    animates (`onboarding-flow.css:578`), the legacy `--transition` alias used 257 times vs 120 for
    `--transition-interaction`, JS timers duplicating CSS durations (`Tooltip.tsx:22`,
    `ContextMenu.tsx:42`, `useAgentMotion.ts:80,111`).

**Phone, worst first**

1. Streaming text `setState` every frame, re-parsing Markdown on the JS thread (`lib/reveal.ts:51-64`).
2. Composer: animated `scrollToEnd` on every content size change, one per dictated word
   (`Composer.tsx:1276,1364`).
3. `LiveWords.tsx:52-70` ~30fps `setState` loop; Talk's countdown sets `width%` every 100ms
   (`talk.tsx:160-170, 401`).
4. One-at-a-time uses `PanResponder` (JS thread) and a default spring, no threshold haptic
   (`one-at-a-time.tsx:304-321`).
5. `RefreshStatus.tsx:52-55` animates height, reflowing the list.
6. No shared motion constants: ~60 literal durations (fade-ins at 120/150/180/200/250/300/400/500),
   two different springify configs; `theme.ts` `duration` has one user.
7. Reduce Motion read once at launch in `talk.tsx:68`, `Composer.tsx:1588`, `LiveWords.tsx:89`,
   `Waveform.tsx:62` (the live hook in `lib/moving.ts` exists).
8. Swipe haptics fire on release, not at the threshold (`AgentRow.tsx:154`, `catch-up:529`);
   `haptic.light` on plain navigation (`result.tsx:181`, `localLinks.tsx:83`).
9. New agent's phases and composer growth pop with no motion (`new-agent.tsx`, `ChatView.tsx:1023`).
10. No swipe to reply in chat (Grok has it; spec 4 uses the reply pill).

**What's already good:** the desk chat's arrival model (`useArrivals`: only new lines move, history
holds still), FLIP sidebar reorders, the global Reduce Motion floor, loops paused when the window is
hidden; the phone's `Arrive` (already on the brand curve), UI-thread keyboard handling, and the
inverted chat list with `maintainVisibleContentPosition`.
